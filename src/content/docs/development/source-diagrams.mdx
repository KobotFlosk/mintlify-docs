Follow how AnE resolves abilities, handles scene choices, and processes requests, reproduction, purchases, and rewards.

For inheritance and compatibility diagrams, see [Ancestry and taxonomy](/system-guide/ancestry-and-taxonomy).

## Ability eligibility

The resolver evaluates your base profile and worn form, then checks the prerequisites and anatomy route for Oviposit. See [Abilities](/system-guide/abilities) and [Oviposit rules](/system-guide/oviposit-rules) for player guidance.

<SourceDiagram file="abilities.md" title="Resolve abilities for base and shifted forms" description="Resolve the base character's abilities and Shift grant. If Shift is granted, check for an active shifted form and resolve its abilities while retaining Shift. Each branch then applies base prerequisites and resolves Oviposit using both profiles." />

## Shared scene choices

The HUD and browser show the same pending choice for a selected partner. A valid reply consumes that choice before advancing the story. See [Answering scene choices](/system-guide/companion-dashboard#answering-scene-choices).

<SourceDiagram file="companion-dashboard.md" title="One scene choice across the HUD and browser" description="An active partner story creates one cached presentation, shown in the HUD and browser. Both reply paths check the owner, handle, and response, then close the handle, run the callback, and return to the story." />

## Request lifecycle

The companion sends an in-world event to the backend and executes the returned actions. See [System overview](/system-guide/system-overview).

<SourceDiagram file="architecture.md" title="From an in-world request to returned actions" description="The in-world object sends HTTP input to the application, which resolves the account, session, and active profile. The current state handles the input and returns actions for the object to execute." />

## Service linking

The one-off portal connects a selected external service and returns to its caller. See [Web portal](/system-guide/web-portal) for the player steps.

## Purchases and rewards

Purchases check the balance and record a debit before delivering an item. Credit rewards can be paid immediately, while product rewards can remain available to claim later. See [AnE Store](/getting-started/operation/ane-store).

<SourceDiagram file="store-and-rewards.md" index={1} title="Purchase confirmation and delivery" description="Browse a product, review its price, confirm the transaction, and check funds. A successful debit leads to item delivery; insufficient funds prevent the purchase." />

<SourceDiagram file="store-and-rewards.md" index={2} title="Grant and claim a reward" description="Find and evaluate rewards, then either process credit rewards immediately or save product rewards unclaimed until the player claims them." />
